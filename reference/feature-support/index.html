Feature support

What works on each platform, and which declared services still have no backend. Function signatures, ownership contracts and errors are in the API reference.

Capability support​

These App services have no backend yet. Their support value is .not_implemented, and every operation returns error.NotImplemented. They allocate no output devices, threads, sessions, files, fake handles, or successful empty results.

App serviceRequests
networkconnection, listening, messages, polling, disconnection
navigationpaths and destinations; no physics or collision access

eggy.network.support and eggy.navigation.support report support without an App. These contracts do not add components to the Inspector.

Working low-level graphics (eggy.vit), UI (eggy.ui), math (eggy.math), ECS (eggy.ecs), scene formats, and asset formats remain available directly. SDL controllers, touch gameplay input, named input maps, value timers, and gameplay time scaling are implemented. Resource reads, model imports and image decoding have owned asynchronous requests with polling, progress and cooperative cancellation. Native requests use bounded worker threads; browser builds defer decoding of already-preloaded data until polling. Scenes.stream loads a scene over several frames behind a loading screen (Stream a scene). Scenes.replace stages synchronous scene replacement for the end of the gameplay update.

See Play sound and 3D audio for sound. Browser builds preload packaged resources through Emscripten, then read them synchronously through SDL. Keep the generated .data file beside the WebAssembly, JavaScript and HTML. Android APKs contain the same packaged data and read it through SDL's AssetManager adapter; APK export targets Android 13 (API 33) through Android 16 (API 36) devices with Vulkan 1.3, through the Android plugin.

Rebuild the editor and game library together after updating Eggy: their ABI is checked, not mixed across revisions. Ownership, Play, and reload explains what happens when Eggy changes under an open editor.
