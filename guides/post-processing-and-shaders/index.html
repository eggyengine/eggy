Post-processing and shaders

Eggy renders the scene in HDR, keeping light brighter than white until the end, then fits it to the screen with post-processing. That last step can tone map, bloom and grade the image. You can also add your own passes and change how a material's surface looks with shaders written in Slang.

Set the look of a scene​

Add an Environment to any entity in the scene (it may already have one). Its post settings are the scene's look:

SettingWhat it does
tone_mappingHow bright light fits the screen. surface (the default) is Eggy's original look: lit surfaces fit themselves and nothing else is mapped. aces is a filmic curve, agx keeps hues as they brighten, reinhard is gentle, and none clips at white.
bloomLight above threshold glows into its surroundings, at intensity. 0 is off.
contrast1 leaves it as it is; higher pushes tones apart.
saturation1 leaves colour as it is; 0 is black and white.
vignetteDarkens the corners, from 0 (none) to 1.
passesYour own post shaders, run in order (see below).

Bloom works best with a tone mapping other than surface. Under surface, lit surfaces are already squeezed below white, so only bright unlit and emissive things glow. For a glowing object, give its material an emissive_color above 1.

The Scene panel shows the look as you change it.

Give one camera its own look​

Add a PostProcess component to a Camera. While that camera is the active one, its settings replace the Environment's: a dream sequence, a security camera, or a hurt player's view. Remove the component to go back to the scene's look.

From code, change the settings like any component:

if (app.world.get(camera, eggy.PostProcess)) |post| {
    post.saturation = 0.2;
    post.vignette = 0.6;
}

Write a post shader​

A post shader runs once for every pixel of the image, before bloom and tone mapping, so it sees the scene's real light values.

  1. In Assets, choose New > Rendering > Post Shader. It makes a .slang file that fades the image towards grey.

  2. Open it in your code editor:

    #include "eggy"

    float4 post(PostInput input) {
        float3 color = sceneColor(input.uv);
        color = lerp(color, luminance(color).xxx, saturate(input.values.x));
        return float4(color, 1.0);
    }

  3. Select the entity with the Environment (or a camera's PostProcess). Drag the shader onto one of passes' shader slots, and set its values. Here the first value is how grey the image gets.

#include "eggy" gives your shader everything below. The function must be called post and take a PostInput:

In PostInputMeaning
uvWhere this pixel is, 0 to 1 from the top left
texelOne pixel's size in uv, for reading neighbours
time_sSeconds the game has run; stands still while you edit or pause
valuesThe pass's four values

sceneColor(uv) reads the image at any point, so a pass can blur, distort or outline. Return the new colour in linear light; values above 1 are fine.

Up to four passes run, each reading what the one before it wrote.

Write a surface shader​

A surface shader changes how a material's surface looks before it is lit: patterns, pulsing glows, colour by height. Eggy still lights and shadows the result.

  1. Choose New > Rendering > Surface Shader. It makes a .slang file with a slow glow.

  2. Edit it:

    #include "eggy"

    Surface surface(SurfaceInput input) {
        Surface shown = defaultSurface(input);
        // Stripes across the world, two metres apart.
        float band = step(0.5, frac(input.world_position.x * 0.5));
        shown.base_color *= lerp(0.6, 1.0, band);
        return shown;
    }

  3. Give a Mesh entity a Material and drag the shader onto its shader slot. A .material.zon file takes a shader too: .shader = "resources/shaders/stripes.slang".

The function must be called surface. defaultSurface(input) is the surface exactly as the material describes it; start from it and change what you need.

In SurfaceInputMeaning
world_positionThe point in the world
normal, view_directionWhich way it faces, and towards the camera, both unit length
uvIts texture coordinates
colorThe material's colour times its texture, in linear light, with alpha
metallic, roughness, emissive, unlitThe material's values
time_sSeconds the game has run
In SurfaceMeaning
base_colorIts colour, in linear light
alphaBelow the material's alpha_cutoff the point isn't drawn
metallic, roughnessHow it reflects light
emissiveLight it gives off, added after lighting
normalWhich way it faces, for lighting
unlitShow base_color as it is, unlit

Shadows ignore a surface shader's alpha: they follow the material's own colour and texture.

When a shader has a mistake​

The editor compiles a shader the first time something uses it, and again when you come back to the editor after changing it. If it doesn't compile, the Console shows Slang's message, pointing at the line in your file, and the mesh or pass is drawn without it.

A shader is a post shader if it takes a PostInput, and a surface shader if it takes a SurfaceInput. Putting one in the other's slot is reported in the Console and skipped.

When you build or export the game, every shader is compiled ahead of time for the platform, web included, so a mistake stops the build with the same message.
