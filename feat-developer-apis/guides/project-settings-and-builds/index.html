Project settings and builds

A game package has src/main.zig with pub const Game; a reusable plugin/library has src/root.zig with pub const Plugin. Use addGame and addPlugin as shown in Plugins. They share the same engine and native ECS types.

Project configuration​

eggy.zon lives beside build.zig.zon:

.{
    .name = "my_game",
    .title = "My Game",
    .version = "0.1.0",
    .default_scene = "resources/scene/start.scene.zon",
    .metadata = .{
        .company = "Example Studio",
        .description = "A small game",
    },
}

name is the package/build name. Players see title. The Project section of Edit > Preferences (File > Project Settings opens it) edits the same configuration, including executable metadata and the startup scene. The runtime is named after the game and the editor is <name>_editor.

Opening <name>_editor directly finds the matching project above the executable, including the usual zig-out/bin/ layout. It checks eggy.zon's name and requires build.zig and build.zig.zon, so a copied editor without its source project stays standalone. If none is found there, it checks the launch directory and its parents; zig build run launches from the project's root, including with a custom install prefix. Use --project <directory> to choose a project explicitly instead.

Developer input overrides live beside this file in controls.zon. Edit > Input Mappings edits them; runtime builds embed them. They are not player preferences. See Input mappings.

Build and export​

CommandResult
zig build allRuntime and desktop editor, without launching
zig build runtime / editorOne executable
zig build runEditor on desktop; runtime browser app on web
zig build run-runtimeStandalone game
zig build runtime -Dscene=resources/scene/start.scene.zonChoose this build's startup scene
zig build exportReleaseFast runtime, packaged resources/libraries, and ZIP

Export needs .default_scene or -Dscene. File > Export asks for a startup scene when necessary. Distribute the exported directory or archive, not just the executable: resource manifests, converted models/images, and required libraries belong with it.

The build honors -Dtarget and -Doptimize. The editor is desktop only. Browser builds use Emscripten and the shared runtime; the default browser resource provider remains unsupported. See the support table for limitations.

Preferences are not save games​

A plugin declares Preferences as a struct with defaulted bool, integer, float, or enum fields. Read values through app.preferences(Preferences). In editor tools use editor.app.preferences(Preferences) directly so changes appear without caching them.

Plugin preferences belong to the project in .eggy/plugins/<published-name>.zon; the game's key is game. The runtime bakes in project preferences. The editor's own settings can additionally have global defaults.

Do not use preferences as a gameplay save format. app.storage is a separate, currently unsupported contract; writing it returns NotImplemented rather than claiming persistence.

Rebuilds and editor tools​

The editor rebuilds changed game code when it regains focus. Game-library replacement keeps scene data but restarts plugin fields and systems. A changed engine requires the editor itself to reload. Keep no references to old plugin instances or component storage.

Plugins can call editor.requestBuild() or requestReload(). They queue existing workflows until the current hook returns. showExport, showNewProject, and showOpenProject likewise open the normal editor workflow rather than pretending to complete it synchronously. Errors and progress use the Console and Build window.

Scene/file tools and undo groups are covered in Editor tools. Logging uses std.log.scoped, which the editor routes to its Console; no separate logger is needed.

Console messages​

Use Errors, Warnings, Info, and Debug to choose which levels are visible; they can be combined, or leave only Errors enabled. The text filter searches the message and its details. Debug messages start hidden unless enabled in Preferences.

The Console keeps its dark terminal background, monospace text, and severity colours. Click a message line to open its selectable, copyable details; click it again to close them. Build errors keep their source excerpt, notes, and reference trace together, even with Info disabled. The Console omits Zig's build-step tree, failed command lines, and redundant build summaries. The Build window still provides the raw output.

Source links open the file at its line and column in your chosen code editor (Edit > Preferences > Code editor). When a compiler error points into Eggy but includes a declaration in your project, the link prefers that declaration. Old editorUi and editorPanelUi signatures are reported with the project declaration and the expected signature, while retaining the compiler's original diagnostic in the details. The system-default editor opens the file but may not jump to the source position.

Hide message dismisses the open message without deleting it; Restore hidden brings dismissed messages back through the current filters. Clear deletes the log. Copy shown copies the filtered messages with their details; Copy message copies the open message, or the selected text in its details.
